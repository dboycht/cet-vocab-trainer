# 源 PDF 缺陷清单与修复证据

> **结论先说**：这本 PDF **不是扫描件**，是被人重排过的「表格版」；它的文本层就是页面真实内容
> （已用高倍渲染逐字核对过若干处）。所以问题不在提取，**在源文件本身**：
> 首词丢字符、词义跨格错位、水印逐字混入格子。
> 下面每条都给出「现象 → 判据 → 处理」，可复核。

## 1. 水印逐字混入词条（已自动修）

**现象**：格子文本里混进 `教` / `际` / `国` 等单字，例如
`'教 overall a.综合的n.工作服'`。

**判据**：水印是**逐字**散布的（不是整段），按文本匹配永远清不干净；
但**字体**能一刀切 —— 真内容只有 `BookmanOldStyle` 与 `SimSun`，水印只有 `KaiTi`。

**处理**：`extract_pdf.py` 在 **span 级**按字体过滤，再把 span 归位到表格格子。
结果：孤儿 span 恰好只剩 30 个页码数字，水印 0 残留。

---

## 2. 中英文被排成「中文在前」（**不是**源文件的错，是我的 bug）

**现象**：`bourgeois a.资产阶级的；平庸的` 被读成 `资产阶级的；平庸的 bourgeois a.`。

**排查**：把该行高倍渲染出来看 —— 页面上**顺序是对的**（英文在前）。所以是提取代码的问题。

**根因**：同一行里 `SimSun` 与 `BookmanOldStyle` 的基线只差 **0.2 pt**（实测 cy 398.0 vs 398.2），
而我用 `round(cy / 4)` 做行分桶 —— 0.2 pt 的差异正好让两者落进**相邻两个桶**，
于是中文被排到了英文前面。一个「看起来无所谓」的取整把 59 个格子读反了。

**处理**：`order_spans()` 改成**按行聚类**（与前一行中心距 ≤ 6 pt 归为同一行），行内再按 x 排序。

**教训**：行分组不能用固定步长取整，必须按距离聚类 —— 不同字体的基线差比想象中小得多。

## 3. 词义跨格错位（已自动修，共 1 处）

**现象**：`block n. 阻塞；障碍物；` 后面没了，而**同一行右格**变成了
`炮闩 damn vt. 诅咒 n. 诅咒；丝毫`。

**判据**：把这一行渲染出来看，页面上**确实就是这么画的**（`炮闩` 真的画在右格里）。
每个词条都以英文首词打头 ⇒ **右格以中文字符开头，这串中文必然属于左格**。

**处理**：`repair_displacement()` 把右格开头的连续中文搬回左格末尾。
修完：左 = `block n.阻塞；障碍物；炮闩`，右 = `damn vt.诅咒 n.诅咒；丝毫`（两条都对上了）。

> 顺带说明：第 2 条修好之前，这个规则被误触发了 59 次（把「中文在前」的行当成错位），
> 修完只剩**真错位 1 处** —— 依赖错误的中间结果去修另一个错误，会放大错误。

## 4. 首词与词性粘连（已自动修，176 处）

**现象**：`suiciden.&vi.&vt.自杀`、`superba.壮丽的`、`tightenvt.&vi.(使)变紧`。

**处理**：取**第一个词性标记的下标**作为切分点 —— 之前的英文是首词，之后是释义。
这个切分是**确定性**的（词性标记都带 `.`，而首词里不含 `.`），所以不需要词典也很安全。

另外源文件偶有词性**丢了点**的情形（`allowance n 津贴，补助费`），
用 `BARE_POS_TAIL_RE` 把首词尾部裸露的词性词剥掉。

## 5. 首词本身损坏（**人工修复 10 处**，见 `tools/headword_repairs.json`）

这是唯一没法自动修的一类。流程：
`vim` 自带的英文拼写词典（离线，`en.utf-8.spl`）先筛出可疑词 → 再用**中文释义必须对得上**定夺。

| 源文件里读到的 | 修复为 | 判据 |
| --- | --- | --- |
| `rmost` | `utmost` | 丢了开头 `ut`；释义 `a.最外面的，最远的` = utmost |
| `outeintegral` | `integral` | 前面多了碎片 `oute`；释义 `a.组成的；整的` = integral |
| `iinfinitely` | `infinitely` | 开头多了一个 `i` |
| `ndefinite` | `indefinite` | 首字符坏（n 应为 i）；同段邻居是 infinitely / unlimited / infinite |
| `ile` | `tile` | 丢了开头的 `t` |
| `twatt` | `watt` | 多了一个 `t` —— 正是左格 `tile` 丢掉的那个 `t`（**跨格字符迁移**） |
| `mishief` | `mischief` | 丢了 `c` |
| `statistics主因` | `statistics` | 格子里窜入中文碎片（的 / 主因） |
| `f scout i` | `scout` | 格子里窜入碎片（f / i / 穗 / 毛边 / 边缘） |
| `i` | `instructor` ⚠️ | **推断**，非逐字恢复：该格文字被行边界裁掉，只剩一个 `i`；释义 `指导者 教员` 对应 instructor |

**⚠️ 最后一条是推断**，在词库里用 `repair_confidence: "inference"` 留了痕，不和「逐字恢复」混为一谈。
其余 9 条的原始拼写都保留在 `source_word` 字段里，可回溯。

## 6. 重复词条（合并义项，2 处）

书里对多义词**真的重复出现两次**，两次释义不同：

- `mint` — `n.造币厂；巨额，富源` / `n.薄荷；薄荷糖`
- `clip` — `vt.剪；剪辑报刊` / `vt.夹住 n.夹子，钳子`

**处理**：合并成一条，义项用 `|` 连接（既不丢词义，也不会在刷词时同一个词出现两次）。

## 7. 复现与复核方式

```bash
python tools/extract_pdf.py      # PDF → .tmp/raw_cells.json（原始格子文本）
python tools/build_wordbook.py   # → assets/wordbooks/cet6.json + .tmp/ 下各类清单
python tools/spellcheck.py       # 离线拼写校验 → .tmp/spellcheck.tsv
node   tools/verify.mjs --data   # 数据门禁：13 项
```

`build_wordbook.py` 每次都会打印：格子条目 / 列错位搬运 / 解析失败 / 去重后唯一词 /
首词修复 / 形态即可疑 / 粘连切分待抽查。
**「形态即可疑」应当恒为 0**，不是 0 就说明又有没识别的缺陷混进来了。

## 8. 残留风险（如实说明）

1. **没有二次人工通读全表**：拼写校验 + 形态校验能抓住「不成词」和「形态异常」，
   但抓不住「恰好是另一个合法英文词」的损坏（例如某词掉了首字母后刚好还是单词）。
   实际未发现此类样本。
2. **没有音标**：源文件没有，离线也拿不到音标库，只能靠浏览器语音合成朗读。
3. **释义未逐条校对**：中文释义直接取源文件，只做了空格与词性排版的规范化。
